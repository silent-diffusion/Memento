# Security audit 2 — 2026-10-11 (before 2.0.0)

Scope: the whole repository at `main` b5ca037 ("Merge the video screens for 2.0"), which holds the full 2.0 surface: video capture, encoding, recovery, playback and export (`src/Memento.Video`, `src/Memento.Core/Video`, the video stage), the camera, the live transcript, known voices and suggested chapters, Tesseract in the worker, the local model's 2.0 changes, keep-only-the-mix, History versions, the clipboard, the tray and Start with Windows, and the 37 bridge methods and 5 events added since 1.0.0. The Release build of the app and worker, the release workflow and the supply chain were checked again. Checklist: ROADMAP.md, "Security audit 2", and audit 1's §9 ("Re-check before 2.0.0"). Threat model and promises: [`../SECURITY.md`](../SECURITY.md). Previous audit: [`SECURITY-AUDIT-2026-10-07.md`](SECURITY-AUDIT-2026-10-07.md); its findings keep their `SA-n` ids, this audit's are `SA2-n`.

## 1. Threat model: what 2.0 changes

The assets, attackers and out-of-scope list of audit 1 §1 stand. 2.0 adds:

- **New assets.** Video tracks (everything shown on a captured display or window, notifications included, and what the camera sees); voice signatures in `<library>\voices\known.json` (biometric-adjacent personal data) and per-recording speaker embeddings in `voices.json`; the live transcript's draft (memory only); clipboard copies of transcripts and documents; the Run value for Start with Windows.
- **New ways in.** A copied-in project folder now also brings MP4 files and `videoTracks[]` entries that recovery, the video stage, Remove video and export read, repair, join or delete; a `known.json` in a library on a shared drive; a window on the desktop whose title, size and display affinity Memento reads for the picker; native code in the worker (Tesseract, Leptonica) next to whisper.cpp, llama.cpp and ONNX Runtime; a `.traineddata` file from the catalog.
- **New capabilities behind the bridge.** Script in the page (attacker 4 of audit 1) could now ask for thumbnails of any listed window or display, start or switch a capture during a recording, remove video, forget voices and keep only the mix. Each needs script in the page, which no finding of either audit made possible (CSP, sanitiser, SA-05).
- **Native search paths.** Media Foundation, Direct3D 11 and the Vortice/SharpGen wrappers load system DLLs by name in the app process; vendor encoder MFTs are loaded by COM.

## 2. Method

As audit 1 (§2), with the same severity scale: **critical** (remote code execution or silent loss of recordings without user action), **high** (a crafted file or text that deletes, overwrites or exfiltrates user data, or crashes a live recording), **medium** (needs one more condition, such as script in the page or a user click, or weakens a stated promise), **low** (defence in depth, availability, hygiene), **info** (no change needed or decided otherwise).

- Read-only review split by area (video pipeline; worker natives and model downloads; new data at rest; bridge surface; network and supply chain), each check ending in a finding or an explicit "no issue found, because …"; every finding traced to file and line and re-checked before it was fixed or accepted.
- Every bridge method added since 1.0.0 enumerated with its parameters (§4).
- **Fuzzing** in the harness style of audit 1 §5 (seeded, deterministic, the same `ByteMutator`, plus structure-aware mutations): the MP4 box reader, crash repair and the remuxer (Media Foundation's MP4 parser), and the manifest's video entries (§5).
- **Network verification** (§6): the in-process spy extended to DNS lookups and run over one whole 2.0 session; the Release app watched at OS level.
- CVE lookup for the bundled native engines (llama.cpp, whisper.cpp, ONNX Runtime, Tesseract, Leptonica) against the exact bundled versions (§3.2).
- Every fix in a small commit with a regression test, after confirming the test fails without the fix where that was possible (the MP4 reader, `project.json` duplicates, the manifest's null entries); all suites green at the end (§8).

Status: **fixed** (commit on this branch), **accepted** (with the reason), **info** (no change needed). No critical or high finding was found; every medium is fixed except SA2-10, which is accepted below with its reason.

## 5. Fuzzing

Same harness style as audit 1 §5: seeded and deterministic, the agenda harness's `ByteMutator` (bit flips, truncation, duplicated chunks, inserted and deleted bytes, interesting values) linked into the new suites, plus structure-aware mutations; each run must end in a result or the documented refusal. Work is measured, not time: the reader's allocations per run are bounded (96 MB) instead of a stopwatch.

- **MP4 reader and crash repair** (`tests/Memento.Video.Tests/Recovery/Mp4FuzzTests.cs`): 3,000 runs over three seeds shaped like Media Foundation's fragmented MP4 (clean with `mfra`, without, torn mid-fragment); a third of the mutations rewrite a box header found by walking the structure (size 0, below the header, past the end, `1` with a 64-bit size of `ulong.MaxValue`, `long.MaxValue`, `2⁶³`, 0, 15, or ±64). Each mutated file goes through `Mp4FileSummary.Read` and then `VideoRecovery.Repair` on disk. Before the fix: 22 of 3,000 escaped (`EndOfStreamException` from reading past a declared size, `ArgumentOutOfRangeException` from a negative position or a short box). After: 0 failures, 3,000 read, 2,230 of them with a torn tail cut; Repair never changed a byte it kept and never cut a refused file. Separate tests: a flood of 2,000,001 empty top-level boxes and a `moov` of 65,537 children are refused without filling memory and the file is left as it is; hostile 64-bit sizes inside `moov` are stopped at, not followed.
- **Remuxer** (Media Foundation's MP4 parser, in process): 120 mutated copies of a real software-encoded 64 × 64 H.264 MP4: 10 remuxed, 110 refused with `VideoCaptureException`, no crash, no hang (each run bounded at 2 minutes), input never changed, no `.tmp` left.
- **Manifest video entries** (`tests/Memento.Core.Tests/Projects/ManifestVideoFuzzTests.cs`): 1,500 runs over a `project.json` with two video tracks of two parts each, at schema 4 and at schema 3 (through the v3 → v4 migration); half byte mutations, half a hostile value in one field of a track or part, the array itself, an added entry or a duplicated `file` key (paths out of the folder, `C:\…`, `\\host\share`, `//host`, `:stream`, `CON.mp4`, `./`, a trailing space, right-to-left override, `mix.flac`, `project.json`, 70,000 characters, ±`long` extremes, `1e308`, booleans, arrays, objects, five-deep nesting, `null`). A load must give a manifest or `ProjectNotFoundException`; a loaded manifest must name no file outside its folder; Remove video must only ever select MP4s in `tracks/`. It found SA2-08 (8 `NullReferenceException`s); after the fix 528 loaded, 972 refused, 0 failures.
- Gaps: Media Foundation's H.264 decoding and the GPU video processor are not fuzzed (export composes from the project's own recordings); an external-data-reference MP4 was not built (SA2-53); Tesseract's recognizer was not fuzzed (it only ever sees host-decoded pixels, SA2-20).

## 6. Network verification

- **In process, a whole 2.0 session** (`tests/Memento.Generation.Tests/Bridge/NetworkSilence20Tests.cs`): the spy (HttpClient diagnostics, `System.Net.Sockets` connects and now `System.Net.NameResolution` lookups, with controls showing it sees each) is started before the host is built. The session turns on the live transcript, Remember speakers by voice and Tesseract; installs whisper-small, Tesseract English and the local model (catalog-shaped test files that pass the hash check); records with the simulated microphone, a screen track and a camera track while the live worker hears windows and returns lines; turns the inset on; stops and lets processing finish; names a speaker, remembers and matches the voice; imports an agenda photo read by Tesseract through the worker protocol (`ocr` job, `recognize`/`recognized` lines); previews, copies the preview of and generates Meeting minutes with the local provider; copies the document and the transcript; and exports the transcript and the video (two files). Result: **no request, no connect, no lookup**; AI stays off; no cloud provider is constructed; no video file name, source name or id, or MP4 box name is in any request, the preview or a clipboard copy. Nothing leaves the PC except the update check (off here) and model downloads the user starts, as SECURITY.md promises.
- **The app itself** (`tools/security/netwatch.ps1` with the Release build, a private data root under `artifacts/`, `--screenshot` and `--simulate-audio`, after SA2-09's DLL search change): the app and its 6 WebView2 processes opened **no TCP connection and no UDP endpoint** in the run (4.9 s), and the library screen rendered.
- **Not verified end to end**: a long interactive 2.0 session in the real window with a real display capture under netwatch (the hardware e2e runs of ENGINE-NOTES §M.8 predate this branch); the worker's real Tesseract job under netwatch (no Tesseract language data on this PC; the scripted worker stands in); a real camera.

## 7. Residual risks

- Script in the page could still capture stills or a window without a Windows border (SA2-10) and read any file under `projects` through `library.memento` (SA2-11). Both need script in the page, which neither audit could produce.
- Native engines parse model files that are only hash-pinned, not sandboxed beyond the worker process: a tampered catalog (tampered binary) would expose the Tesseract 5.5.1 and llama.cpp model-parsing CVEs (SA2-24, SA2-25). The worker can still start programs (SA2-22).
- Media Foundation still decodes imported media and the project's own video in the app process (SA-59 was not moved to the worker in 2.0); limits, timeouts and the fuzzed reader bound it, but a native decoder bug can still crash the app and a recording in progress.
- The restarted camera track of a crashed recording is kept on disk but not added to the recording (SA2-03).
- Voice confirmations can outlive a deleted recording when `known.json` cannot be rewritten (SA2-36); clipboard history can hold copies (SA2-38).
- Unsigned installers and updates; lockfiles and SHA-pinned actions still not in place (SA2-63).
